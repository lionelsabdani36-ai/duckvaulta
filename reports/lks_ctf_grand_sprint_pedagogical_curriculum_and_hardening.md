### 3. DEKOMPOSISI FIRST PRINCIPLES 5 DOMAIN UTAMA TIER 1 MEDIUM SWEEP

Mari kita bedah secara ilmiah konsep fundamental yang mengendalikan 19 modul pada Tier 1 Medium Sweep. Tidak ada satu pun tantangan yang boleh dipandang sebagai tebak-tebakan; semuanya tunduk pada hukum arsitektur komputer.

#### DOMAIN 1: SMART CONTRACT & BLOCKCHAIN SECURITY (Chall 760 Smart_Overflow, Chall 723 Access_Control)
1. First Principles Representasi Aritmatika EVM (256-Bit Word):
EVM menggunakan register 256-bit standar. Rentang nilai tipe data `uint256` adalah dari 0 hingga 2^256 - 1 (setara dengan 1.1579 x 10^77). Pada arsitektur compiler Solidity di bawah versi 0.8.0, operasi aritmatika dasar (+, -, *) dijalankan langsung melalui opcode EVM mentah (`ADD`, `SUB`, `MUL`) tanpa validasi status overflow flag.
Ketika sebuah akun memiliki saldo 0 dan mengeksekusi operasi:
`balance = balance - 1;`
Nilai 0 biner (0x00...00) yang dikurangi 1 akan mengalami underflow mekanis menjadi representasi komplemen biner tertinggi:
`0xFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFF`
Akibatnya, saldo penyerang secara instan melonjak menjadi 2^256 - 1 unit token.

2. Dekomposisi Storage Slot & Kontrol Akses (Chall 723):
Storage smart contract di EVM dipetakan sebagai array asosiatif 2^256 slot berukuran 32-byte. Deklarasi variabel `private` pada Solidity hanyalah pembatasan visibilitas tingkat bahasa tingkat tinggi (compiler guard) untuk mencegah kontrak lain memanggil getter otomatis. Data yang tersimpan di dalam slot storage tetap terbaca 100% secara publik di blockchain melalui RPC method `eth_getStorageAt(contractAddress, slotPosition)`. Jika fungsi pengubah state kepemilikan (`setOwner()` atau initializer) tidak diproteksi modifier `onlyOwner`, siapa pun dapat mengirimkan transaksi mentah untuk mengambil alih hak akses kontrak.

#### DOMAIN 2: BINARY EXPLOITATION & MEMORY INTEGRITY (Chall 733 offset-cycle, Chall 133 Binary Gauntlet 3, Chall 487/489 hash-only)
1. Aljabar Offset Stack Frame & De Bruijn Sequence (Chall 733):
Pada arsitektur AMD64 (x86_64), alokasi variabel lokal di stack tumbuh ke arah alamat memori yang lebih rendah. Struktur stack frame fungsi standar adalah:
`[Buffer Lokal] -> [Saved RBP (8 byte)] -> [Saved Return Address / RIP (8 byte)]`
Untuk menghitung jarak presisi antara awal buffer lokal dengan return address, kita memanfaatkan sekuens De Bruijn modulo N, di mana setiap sub-string dengan panjang K bersifat unik. Saat string siklis ini disuntikkan dan program memicu Segmentation Fault, nilai register RIP yang crash (misal: 0x6161616a) langsung dipetakan kembali ke indeks polinomial sekuens tanpa perlu melakukan tebak-tebakan manual.

2. Mitigasi No-Execute (NX) & Rekayasa ROP Chain (Chall 133):
Saat bit NX/DEP aktif pada tabel halaman virtual memory (PTE bit 63 diaktifkan), instruksi prosesor menolak mengeksekusi kode apa pun yang berada di stack segment. Shellcode klasik menjadi tidak berguna.
Solusinya adalah Return-Oriented Programming (ROP): memanfaatkan serangkaian potongan instruksi assembly pendek yang diakhiri oleh opcode `RET` (0xC3) yang telah ada di segmen kode executable (libc atau biner).
Sesuai konvensi System V AMD64 ABI, argumen pertama sebuah fungsi wajib dimasukkan ke register `RDI`. Maka, rangkaian eksekusi ret2libc disusun sebagai berikut:
- Gadget `pop rdi; ret`: Memindahkan pointer string "/bin/sh" dari stack ke register RDI.
- Alamat string `"/bin/sh"`: Berada di segmen read-only libc.
- Alamat fungsi `system()`: Dieksekusi dengan RDI yang telah menunjuk string tersebut.
- Penyeimbang Stack Alignment: Menyisipkan gadget `ret` tunggal sebelum pemanggilan `system()` untuk menjaga keselarasan stack 16-byte (memenuhi syarat instruksi `movaps` pada glibc modern).

3. Injeksi Perintah & Batas Hak Istimewa SUID (Chall 487 & 489):
Pemanggilan biner sistem melalui `system(command_string)` menjalankan `/bin/sh -c command_string`. Jika biner beroperasi dengan bit SUID (Set User ID) aktif dan mengeksekusi utilitas eksternal dengan nama relatif (misal: `md5sum filename`), penyerang dapat memanipulasi variabel lingkungan `PATH`:
`export PATH=/tmp:$PATH`
Dengan menempatkan biner buatan sendiri bernama `md5sum` di `/tmp` yang berisi perintah spawn shell, biner SUID akan mengeksekusi payload penyerang dengan hak akses penuh pemilik biner (root).

#### DOMAIN 3: REVERSE ENGINEERING & SYMBOLIC EXECUTION (Chall 754 Autorev 1, Chall 479 Quantum Scrambler, Chall 116 speeds and feeds)
1. Otomasi Constraint Solving Symbolic Execution (Chall 754):
Ketika sebuah biner mengimplementasikan ratusan percabangan bersarang untuk memvalidasi input, dekompilasi manual menjadi tidak efisien. Kita memperlakukan input pengguna sebagai variabel simbolik alpha in {0, 1}^(8*L).
Menggunakan symbolic execution engine (angr):
- Definisikan state awal dengan input simbolik berukuran L byte.
- Tetapkan batasan karakter ASCII yang dapat dicetak (0x20 <= alpha_i <= 0x7E).
- Jalankan simulasi path explorer menuju basic block alamat sukses (find=addr_win) dan hindari basic block kegagalan (avoid=addr_fail).
- Mesin Z3 SMT solver internal akan menyelesaikan sistem persamaan Boolean secara otomatis dalam fraksi detik.

2. Dekonstruksi Permutasi Kriptografis Invers (Chall 479):
Permutasi deterministik adalah pemetaan bijektif pi: {0, ..., N-1} -> {0, ..., N-1}. Sehebat apa pun istilah kuantum yang digunakan dalam narasi soal, jika transformasi terhadap array karakter C didefinisikan sebagai:
C'[j] = C[pi(j)]
Maka fungsi pemulihannya adalah invers permutasi pi^(-1):
C[i] = C'[pi^(-1)(i)] di mana pi^(-1)(pi(j)) = j
Dengan mengekstrak array indeks pemetaan dari biner, flag asli dipulihkan secara instan melalui operasi pengindeksan balik.

3. Rekonstruksi Trajektori Geometris G-code CNC (Chall 116):
G-code adalah bahasa standar kontrol numerik terkomputerisasi (RS-274D). Perintah G00 merepresentasikan gerakan positioning cepat tanpa kontak material, sedangkan G01 adalah gerakan interpolasi linier pemotongan.
Dengan memfilter baris data koordinat:
Saat Z < 0 (mata pahat menusuk material), simpan segmen garis (X1, Y1) -> (X2, Y2).
Dengan memproyeksikan seluruh segmen garis ini ke canvas visual 2D menggunakan matplotlib, karakter teks flag LKS akan terbaca secara visual dari pola goresan mesin CNC.

#### DOMAIN 4: DIGITAL FORENSICS & RECOVERY MEMORI (Chall 453/454 Bitlocker, Chall 284 Operation Oni, Chall 481 flags are stepic)
1. Arsitektur Enkripsi Volume BitLocker & Carving Kunci Pemulihan:
BitLocker melindungi volume disk menggunakan enkripsi AES-CBC atau XTS-AES 128/256-bit. Volume Master Key (VMK) dilindungi oleh Full Volume Encryption Key (FVEK). Jika sistem berada dalam kondisi aktif saat disita, FVEK tersimpan di memori volatile (RAM) atau file hiberfil.sys.
Pada level dasar (Bitlocker-1), kunci pemulihan numerik 48-digit (8 blok 6-angka: XXXXXX-XXXXXX-...) sering kali tersimpan secara plaintext pada unallocated disk space atau file catatan sementara. Kunci dapat dicarve menggunakan ekspresi reguler presisi:
`\b[0-9]{6}(-[0-9]{6}){7}\b`
Volume kemudian di-mount pada Linux menggunakan utilitas dislocker-fuse:
`dislocker -V /dev/loopX -p<RECOVERY_KEY> -- /mnt/bitlocker`
`mount -o loop /mnt/bitlocker/dislocker-file /mnt/decrypted`

2. Forensik Partisi Ext4 & Ekstraksi Kunci Kredensial SSH (Chall 284):
Pemeriksaan image disk mentah (raw image) dimulai dengan identifikasi tabel partisi DOS/MBR atau GPT menggunakan fdisk -l.
Hitung byte offset partisi root Linux:
Offset = Start Sector x 512 byte/sector
Setelah partisi di-mount secara read-only (`mount -o ro,loop,offset=N`), penyidik forensik memprioritaskan ekstraksi artefak autentikasi persisten: direktori `/home/*/.ssh/` dan `/root/.ssh/`. Private key OpenSSH (`id_rsa` atau `id_ed25519`) yang tertinggal memberikan akses remote shell tanpa password ke infrastruktur server target.

3. Steganografi Least Significant Bit (LSB) Format PNG (Chall 481):
Modul Python stepic menyisipkan bit-bit informasi rahasia ke dalam bit paling tidak signifikan (LSB, bit ke-0) dari komponen warna byte piksel merah, hijau, dan biru (RGB). Perubahan nilai biner dari misal 0b11111110 menjadi 0b11111111 hanya mengubah intensitas warna sebesar 1/256, yang secara mutlak tidak terlihat oleh mata manusia.
Ekstraksi pesan dilakukan secara deterministik dengan membaca bit ke-0 dari setiap channel warna secara sekuensial hingga menemui karakter terminator null:
```python
from PIL import Image
import stepic
img = Image.open('flag.png')
secret_data = stepic.decode(img)
```

#### DOMAIN 5: MODERN WEB EXPLOITATION & LOGIC FLAWS (Chall 443 No Sql Injection, Chall 355 Java Code Analysis, Chall 480 WebSockFish)
1. Injeksi Operator Boolean NoSQL MongoDB (Chall 443):
Pada aplikasi Node.js/Express yang menggunakan body parser JSON (`app.use(express.json())`), input form yang dikirim oleh pengguna tidak selalu bertipe string. Jika aplikasi mengirimkan:
`{"username": "admin", "password": {"$ne": "invalid_pass"}}`
Dan backend mengeksekusi query Mongoose secara naif:
`db.collection('users').findOne({username: req.body.username, password: req.body.password})`
MongoDB akan mengevaluasi operator `$ne` (Not Equal). Query mencari dokumen di mana username adalah 'admin' DAN password TIDAK SAMA DENGAN 'invalid_pass'. Karena password asli admin di database tentu bukan 'invalid_pass', kondisi bernilai TRUE dan pengguna berhasil masuk sebagai administrator tanpa pernah mengetahui password aslinya.

2. Verifikasi Token Kriptografis JWT & Forgery Role Admin (Chall 355):
JSON Web Token (JWT) terdiri dari tiga bagian terpisah titik: Header, Payload, dan Signature yang di-encode Base64URL.
Pada algoritma simetris HMAC-SHA256 (HS256), signature dihitung sebagai:
`Signature = HMAC-SHA256(Header || Payload, SecretKey)`
Jika secret key penandatanganan di-hardcode di dalam source code Java (misal: di file controller atau konfigurasi Git publik), integritas token runtuh sepenuhnya. Penyerang dapat merekonstruksi token baru dengan memodifikasi payload menjadi `{"role": "Admin", "user": "arielwin"}` dan menandatanganinya kembali menggunakan secret key yang bocor.

### 6. MODEL PSIKOMETRIK IRT 3PL & RUBRIK PENILAIAN LKS SKILL 54

Tingkat penguasaan White Jack dan Arielwin diukur menggunakan model psikometrik Item Response Theory (IRT) model logistik 3 parameter (3PL):
$$P_i(\theta) = c_i + \frac{1 - c_i}{1 + e^{-a_i (\theta - b_i)}}$$
Di mana:
- theta: Tingkat kemampuan laten siswa (kemampuan analitis siber, skala -3.0 s.d. +3.0).

- b_i: Parameter tingkat kesulitan soal (difficulty parameter, rentang target +1.0 s.d. +2.5).
- c_i: Parameter pseudo-guessing (probabilitas menebak benar secara kebetulan, target < 0.05).

### 7. PANDUAN REMEDIASI DEFENSIF STANDAR INDUSTRI (NIST SP 800-115 & NIST SP 800-53 REV. 5)

Sebagai calon profesional keamanan siber dan pemenang LKS, kalian wajib menguasai sisi penyerangan (offensive) dan pertahanan (defensive) secara seimbang. Setiap kali sebuah kerentanan berhasil dieksploitasi, kalian harus mampu menyusun rekomendasi hardening berbasis standar NIST SP 800-115:

#### 7.1 Remediasi Kontrak Pintar (Smart Contract Hardening)
- Safe Arithmetic Enforcement (Kontrol NIST: SI-10 Information Input Validation):
  Wajib mengadopsi compiler Solidity versi >=0.8.0 di mana seluruh operasi aritmatika secara bawaan memicu transaction revert saat terjadi overflow/underflow. Untuk basis kode warisan (legacy), wajib membungkus seluruh kalkulasi numerik dengan pustaka OpenZeppelin SafeMath.
- Strict Ownership & Access Guardrails (Kontrol NIST: AC-3 Access Enforcement):
  Terapkan modifier onlyOwner atau AccessControl berbasis peran (RBAC) pada setiap fungsi pengubah state penting. Inisialisasi kontrak wajib dikunci menggunakan constructor yang aman atau mekanisme Initializable OpenZeppelin untuk kontrak berbasis proxy.

#### 7.2 Remediasi Biner & Stack Hardening
- Compiler Hardening Flags (Kontrol NIST: SI-16 Memory Protection & SA-8 Security Engineering Principles):
  Setiap kompilasi aplikasi berbasis C/C++ untuk lingkungan produksi wajib menyertakan flag proteksi modern:
  `gcc -fstack-protector-strong -D_FORTIFY_SOURCE=2 -Wl,-z,relro,-z,now -fPIE -pie -O2 application.c -o application`
  - `-fstack-protector-strong`: Menyisipkan stack canary untuk mendeteksi penulisan melampaui buffer lokal sebelum fungsi mengembalikan nilai (mencegah eksploitasi saved RIP).
  - `-Wl,-z,relro,-z,now` (Full RELRO): Menjadikan Global Offset Table (GOT) sepenuhnya read-only setelah proses linking selesai, mencegah teknik GOT overwrite.
  - `-fPIE -pie`: Menghasilkan executable independen posisi (Position Independent Executable) yang memaksimalkan entropi pengacakan alamat ASLR pada segmen kode.
- Safe Subprocess Invocations (Kontrol NIST: SI-10):
  Larang keras penggunaan fungsi `system()` atau `popen()`. Jalankan proses eksternal hanya melalui keluarga fungsi `execve()` dengan path biner absolut (misal: `/usr/bin/md5sum`) dan array argumen terpisah secara tegas tanpa memanggil shell perantara.

#### 7.3 Remediasi Web Application & Database Query
- Skema Validasi Input Ketat (Kontrol NIST: SI-10 & AC-3):
  Pada endpoint aplikasi web, terapkan skema validasi tipe data menggunakan pustaka seperti Zod, Joi, atau Pydantic. Pastikan field password dan username berjenis string murni dan memiliki batas panjang karakter (misal: min 8, max 64).
  Untuk database NoSQL MongoDB, gunakan middleware pembersih operator seperti express-mongo-sanitize yang secara otomatis melucuti karakter `$` dan `.` dari payload request pengguna.
- Key Vault Management (Kontrol NIST: SC-12 Cryptographic Key Management):
  Kunci rahasia penandatanganan JWT atau kredensial enkripsi tidak boleh disimpan di dalam repositori kode (hardcoded secrets). Wajib gunakan Environment Variable terisolasi atau layanan Key Management Service (HashiCorp Vault / AWS Secrets Manager).

#### 7.4 Remediasi Endpoint & Disk Forensics
- Enkripsi Disk Penuh (FDE) & TPM Binding (Kontrol NIST: SC-28 Protection at Rest):
  Aktifkan enkripsi BitLocker dengan autentikasi hardware TPM 2.0 dan PIN pra-boot. Nonaktifkan mode penyimpanan sleep/standby yang membiarkan kunci enkripsi tersimpan di RAM tanpa proteksi.
  Larang keras penyimpanan Recovery Key dalam file teks biasa di lingkungan kerja; kunci wajib disimpan dalam repositori Active Directory terenkripsi.
